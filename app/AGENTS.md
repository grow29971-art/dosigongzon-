# app/ — 화면·컴포넌트

## 범위

라우트(페이지·레이아웃)와 공용 UI(`app/components/`). 데이터 접근 로직은 이 모듈 소관이 아니다 —
쿼리가 필요하면 `lib/`의 repo 함수를 호출하고, 없으면 lib에 만들어서 쓴다. 컴포넌트 안에
supabase 쿼리를 직접 작성하지 않는다.

## 구조 규칙

- `app/(main)/*`는 BottomNav가 있는 메인 셸. 랜딩·로그인·가입·welcome·약관은 셸 밖 루트 라우트.
- 읽기 전용 페이지는 서버 컴포넌트로(보호지침 페이지들이 표본). 인터랙션이 필요할 때만
  `"use client"`. `useRouter().back()`이 필요하면 그 부분만 클라이언트 컴포넌트로 분리.
- 홈은 세션 유무로 `HomeLanding`(비로그인, SEO SSR)과 `HomeAuthed`(로그인, 클라 fetch)로 갈린다.
  이 분기는 `getSession()`(쿠키 파싱만)을 유지할 것 — `getUser()`로 바꾸면 홈 TTFB가 급증한다.
- 비로그인 화면에서 고양이 데이터를 읽을 땐 `cats_public_map` 뷰 기반 경로만 — base `cats`에
  임의 필터를 걸면 anon 컬럼 권한으로 프로덕션에서만 빈 결과가 난다.

## 지켜야 할 것

- 사용자 노출 문자열은 전부 한국어. 위험 상태 등 도메인 라벨은 `HEALTH_MAP` 같은 lib 상수를
  참조하고 화면에 리터럴로 다시 쓰지 않는다.
- 색·그림자·라운드는 기존 CSS 변수/토큰(`--color-primary`, `--shadow-card` 계열)을 쓴다.
  새 hex 하드코딩 금지(테마 동결 중). 아이콘은 lucide-react.
- 저활용 기능 제거는 삭제가 아니라 `SHOW_*` 플래그 숨김으로.
- 사용자 입력에서 온 URL은 렌더 전에 `sanitizeImageUrl`/`sanitizeHttpUrl`을 반드시 통과시킨다.
- 추모(`memorial_at` 있는) 고양이에게 돌봄 권유·입양 문의 UI를 띄우지 않는다 — 조건 분기 누락이
  잦은 지점.

## 테스트 관점

- 화면 자체는 E2E 없이 배포 후 프로덕션 curl 실측으로 확인하는 게 관례(SSR 문구·상태코드).
- 화면에서 분리된 순수 로직(온보딩 스텝 순서·플래그 계산)은 `tests/`에 단위 테스트가 있다 —
  해당 로직을 바꾸면 그 테스트부터 갱신.
