# 0009 — 커뮤니티 봇을 "글 생산자"에서 "유저 글 첫 반응자"로 되돌림 (2026-09-18 원탁회의)

1. 유저 글 첫댓글 크론(`community-comment`, 매일 20:30)은 실행되지만 **매일 스킵** — 20h 전역 쿨다운이
   `author_title=staff` 댓글 전부를 세는데 exe 봇↔봇 댓글이 매일 있어 항상 "최근 운영 댓글 존재". cron_runs 9/16·17 확인.
2. 9/6 글 작성자는 **탈퇴**(author_id null, posts에 59건). 그 사람에겐 어떤 수정도 못 닿음. 방문자 눈엔 "죽은 글".
3. 봇 글 22건은 크론(월수금 1건)이 아니라 exe 산. 서버 캡 15/일.
4. "운영" 배지는 9/16 사장님 지시로 화면 숨김(ad89bdee). 회의 브리프의 "표시 필수" 전제가 낡았음 — 메모리 정정.
5. 커뮤니티는 읽기부터 로그인 벽(UI). 데이터(posts/post_comments/care_logs)는 RLS상 이미 anon SELECT 허용.

7. 새 유저 글 → 사장님 알림 경로 없음(텔레그램은 발주·환불만, admin-daily-digest는 posts 미포함).
8. 이메일 다이제스트 `email_digest_enabled=true` 52명 — default true 잔여분(동의자 아님). 푸시 구독 행 56.

### 기각 (악마의 변호인 채택)
- 커뮤니티 읽기 벽 제거 — 데이터는 이미 공개지만 화면·검색엔진 노출은 "닉네임→고양이 상세→QR 자리" 표적화 체인의 첫 고리를 익명화. 상세 1페이지 공개도 인터뷰 후.
- 글·댓글 위치 텍스트 클라이언트 차단 — 하드가 아니고(REST 우회), 정규식 `[가-힣]{2,}시장`이 9/6 글("동네시장 생선가게")을 막았을 오탐. 하려면 DB 트리거 + 화이트리스트 설계 후.
- 댓글 크론 매시 실행 — 대상 글 주 0.15건에 주 168회 빈 실행.
- 고양이 상세 돌봄 명부 스트립("○○님 12회·마지막 밥 2일 전") — 실물 QR과 결합 시 ±444m 퍼징 무의미.
- 고양이 상세→글쓰기 프리필, 게시판 "운영진 작성 글 포함" 고지문, 후보 창 30일 확장, 긴급 카테고리 봇 응답.

### 보류 — "계속 쓰는 이유" (리텐션 훅, 사장님 판단)
3관점(도메인·BM·리텐션루프)이 같은 답: **주간 개인 확인서 이메일** — 기존 `weekly-digest`(월 08시)의 전체 소식을
"지난주 ○○님: 기록 N건 · 기록 없는 아이 · 확인서 누적 활동일"로 교체. `getMyCareReportServer` 재사용, DB 0, 2~3커밋.
악마의 반론으로 **선행 조건 2개**가 붙음: (a) 기록 0인 수신자(52명 중 45명+)에겐 개인 섹션 생략 또는 미발송 —
"당신이 등록한 고양이가 5일째 굶는다" 죄책감 프레임·고양이 삭제 유발 방지, (b) 측정 수단 — `captureSource`는
first-touch 1회만 저장해 기존 유저의 이메일 UTM 유입이 안 잡힘. 별도 이벤트 없이는 성공·실패 판정 불가.
대타 매칭(위치 계약 충돌·밀도 0)·街猫(하드웨어·라이브=위치 공개)·치료비 모금(기부금품법)·스트릭 포장은 기각.
`NEXT_PUBLIC_FF_CJ_CARE_SHIFT` ON은 0커밋 프로브로 허용(4주 `care_shifts` 행 0이면 OFF).

## 판정 기준 (4주, 실유저·봇·관리자·시드 제외, 건수 지표 배제)
- 유저 글 → 첫 댓글 24h 이내 100%(현 0%).
- 서로 다른 실유저 ≥5명이 글/댓글, 그중 ≥2명이 14일 간격 재활동. 8주 미달이면 "커뮤니티에서 놀게 하기" 기각.
- 봇 글 1건당 조회 중앙값 ≥3(현 0). 봇 감량은 성장이 아니라 손실 중단 — 게시판이 더 비어 보이는 것은 예상된 결과.
- 표본 부족으로 판정 자체가 무효일 확률이 높음을 사전 합의. 부정 확정만 가능, 긍정 확정은 불가.
