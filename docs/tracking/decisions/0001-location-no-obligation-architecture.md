# 0001 — 위치정보 무의무 아키텍처

## 배경

길고양이 위치는 서비스의 핵심 데이터인 동시에 학대 표적 정보다. 실좌표를 수집·제공하면
위치기반서비스(LBS) 사업 신고 의무가 생길 수 있고, 학대 리스크도 커진다. 2026-07 법무 검토와
08-10 판정에서 방향을 정해야 했다.

## 결정

**실좌표를 아예 시스템에 들이지 않는다.** 등록·수정 시 브라우저에서 ±444m 랜덤 오프셋을 적용한
좌표만 전송·저장한다 — 실좌표는 네트워크로도 나가지 않고 DB에도 없으므로, 법적 의미의 정확한
위치정보를 "수집·이용·제공"하지 않는 구성이 된다. LBS 별도 신고는 하지 않는다. 여기에 더해
비로그인 조회에는 결정적 퍼징 500m를 추가(합산 최대 ±900m)하고, 급식소 정확 위치는 텍스트로도
금지, 사진 GPS EXIF는 자동 제거한다.

## 검토한 대안

- **실좌표 저장 + 조회 시 권한별 퍼징** — 서버·DB에 실좌표가 존재하는 순간 수집에 해당할 소지가
  있고 유출 시 피해가 실좌표 단위라 기각.
- **LBS 사업 신고 후 정확 좌표 제공** — 신고·관리 부담이 1인 운영에 과중하고, 학대 리스크는
  신고로 해결되지 않아 기각.
- **좌표 자체를 안 받는 동 단위 서비스** — 지도 서비스의 핵심 가치(핀)를 죽여서 기각.

## 결과와 제약

- **정밀 위치 기능은 이 서비스에서 원천적으로 불가능하다** — "내 고양이 정확 위치 보기" 같은
  요청은 데이터가 없어서 만들 수 없고, 만들려는 시도(오프셋 우회 등록 경로)는 법적 지위를 바꾸는
  변경이라 사장님 승인 사안.
- 고양이 등록·수정의 모든 경로는 오프셋 함수를 반드시 거쳐야 한다 — 과거 수정 경로 하나가
  누락돼 정확 좌표가 저장되던 회귀가 있었고, 단일 함수로 봉합했다.
- 로그인/비로그인 응답 좌표가 다르므로 좌표 응답의 익명 공유 캐시가 금지된다(성능 최적화의 제약).
- anon의 base 테이블 접근이 컬럼 그랜트로 잠겨 있어, 비로그인 조회 기능은 항상 공개 뷰를 거쳐야
  한다(개발 시 우회 불가).
