## 커뮤니티 글·댓글이 위치 텍스트 차단을 안 탄다 (2026-09-18)

- 증상: `findLocationViolations`(lib/location-patterns.ts)는 cats-repo·AddCatModal·zone-report·circle-chat·dm에서만 호출되고
  `lib/posts-repo.ts`(게시판 글·댓글)에는 연결돼 있지 않다. docs/security.md의 "공개 게시물의 위치성 텍스트는 하드 차단"
  서술과 실제 구현이 불일치.
- 영향: 자유게시판에 "OO아파트 앞에서 밥 주는 분" 같은 텍스트로 돌봄자 특정이 가능. 지금 트래픽(유저 글 월 1건)에선
  즉시 사고 확률 낮음. 유입을 늘리기 전에 막는 게 순서.
- 지금 못 푸는 이유: 글·댓글 insert가 브라우저 클라이언트라 코드 한 줄은 "하드"가 아니고(REST 우회 가능), 진짜 하드는
  DB 트리거 = SQL 실행 게이트. 게다가 현재 정규식(`[가-힣]{2,}시장` 등)은 9/6 유일한 실유저 글("동네시장 생선가게")을
  막았을 오탐 — 도움 요청 글의 본질이 "어느 아이인지 특정"이라 화이트리스트 설계 없이는 실유저 글의 유일한 장르를 죽인다.
- 접근: (1) security.md 서술을 실제(고양이 설명·제보·채팅·DM만)로 정정, (2) 유입 확대 결정 시 DB 트리거 + 오탐
  화이트리스트로 설계. 결정 기록 decisions/0009.

  여러 개 뜨거나 콜드 스타트가 잦으면 상한을 넘겨 발송될 수 있다.
- 영향: 현재 볼륨(일 케어 수 건)에선 실해가 없지만, 케어 기록이 하루 수백 건이 되면 하트 유저에게

  과설계라 보류.
- 접근: 볼륨 증가 시 발송 이력 테이블(cat_id·sent_at) + 마이그레이션으로 전환.

## (해결) DOMPurify 서버 정화가 폴백 경로로 도는지 확인 필요 (2026-09-16) — 9/17 실측 매 요청 폴백 → sanitize-html로 교체(611933ea)

- 증상: `/tips/[slug]`의 렌더 시점 DOMPurify(jsdom) 정화가 Node 20에서 모듈 로드 실패(ERR_REQUIRE_ESM)해
  정규식 sanitizer로 폴백하도록 고쳤고(8b4aeebd), `engines.node=22.x`도 지정했다. 배포 직후 로그에 폴백 1건이
  찍혀 있어 Node 22 적용 후 DOMPurify 정상 경로가 도는지 아직 확인되지 않았다.
- 영향: 폴백도 write-time과 같은 화이트리스트 정화라 XSS 방어선은 유지되지만, mutation XSS 이론적 여지가
  DOMPurify보다 크다(관리자 self-XSS 한정).
- 접근: 다음 배포 후 Vercel 로그에서 "폴백" 검색 → 0건이면 종결. 남아 있으면 `html-encoding-sniffer`를 5.x로
  overrides 고정하거나 jsdom 없는 sanitizer로 교체.
