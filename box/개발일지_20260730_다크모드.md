## 1. 1차 시도 — 표준 opt-out (`f7059c8`) : 실패

- `color-scheme: only light`(CSS+meta) + `themeColor`를 CSS 변수→실hex(#F9FAFB) 교정
  + Tailwind 4 `dark:` 변형을 `@custom-variant dark (&:where(.dark, .dark *))`로 클래스 기반 전환
  (기본값이 시스템 미디어쿼리라 RescueBanner 등이 시스템 다크에 반응하던 것 차단).
- 배포 후에도 "아직도 어둡게 나와" → 재현 환경 구축으로 전환.

## 2. 헤드리스 크롬 실측 (크롬 150, `--headless=new` + 강제다크 플래그 조합)

| 페이지 선언 | prefers-dark 없이 강제다크 | prefers-dark + 강제다크 |
|---|---|---|
| `only light` | **반전됨** (opt-out 무시) | 반전 안 됨 |
| `light dark` | 반전됨 | **반전 안 됨 + author 라이트 유지** |

- 핵심 발견 ①: `only light` opt-out은 강제다크 경로 일부에서 무시됨.
- 핵심 발견 ②: WebView(카톡/네이버 인앱)의 알고리즘 다크닝은 **"다크 미지원 사이트"만 골라 반전**
  → `only light` 선언은 오히려 반전 대상임을 자백하는 셈.
- 결론: **"다크 지원 선언(light dark) + 실제 스타일은 항상 라이트"**가 유일한 전 브라우저 방어.
