## 2. 동네 돌봄 실험 — '한 동네 돌봄자 5명' 14일 실험 MVP

### 목적
총 회원 수가 아니라 **특정 지역에서 돌봄 행동이 반복되는지** 검증.
핵심 지표: 주간 반복 기록자 / 초대→첫 기록 전환 / 첫 기록자 다음 7일 재기록 /
1인당 주간 기록 수 / 초대 수·수락 수.

### 설계 결정 (가정 명시)
- 기존 `care_logs`는 고양이 개체 단위(좌표 연결)라 재사용 불가 판정 → `experiment_care_logs` 신설
- `funnel_events`는 unique(anon_id, step) 1회성 구조라 반복 이벤트에 부적합 → `experiment_events` 신설
  (**건수 전용 — user_id/위치/메모/사진 절대 저장 안 함**)
- 초대 토큰: 1회용, 원문은 DB에 저장하지 않고 **sha256 해시만** 저장, 만료 14일
- 실험 생성자는 자동 참여 (초대의 출발점)
- 쓰기는 전부 서버 API(service_role) 경유 — 기간·멤버십·정지·1회용 토큰 검증을 코드에서 강제,
  RLS는 클라이언트 쓰기 기본 거부(2차 방어). 읽기 RLS는 "내 것 + 내가 속한 실험 메타"만.
- 중복 방지: 참여는 pk(experiment_id,user_id), 기록은 unique(experiment,user,cared_on,type) 멱등 upsert
- 날짜는 서버에서 KST 고정(`lib/kst.ts`) — 클라이언트 날짜 조작 불가

### 파일
- DB: `box/supabase_experiment_migration.sql` (5테이블+RLS+롤백) — **사장님 SQL Editor 실행 필요**
- lib: `experiments-repo.ts`(타입·상수·초대문구), `experiment-metrics.ts`(순수 집계), `experiments-server.ts`(서버 헬퍼)
- API: `/api/experiment/{invite,join,care-log,summary,event}`, `/api/admin/experiments`(GET목록·지표/POST생성/PATCH상태)
- 화면: `/experiment`(참여자 대시보드 — 오늘 돌봄 완료·공동 성과·초대), `/experiment/join/[token]`(초대 랜딩+OG 메타), `/admin/experiments`(생성·지표)
- 검증: `scripts/test-experiment-metrics.ts` (`npx --yes tsx`로 실행)

### 남용 방어
- 초대 생성: 유저당 분당 5회 + 미사용 활성 초대 30개 상한
