# 【필수】가상상품 등록 전 선행조건 체크리스트

> 이 문서는 "나중에 처리"가 잊히는 걸 막기 위한 **하드 게이트**다.
> 아래 항목이 전부 끝나기 전에는 `products.is_virtual = true` 상품을 등록하지 말 것.
> 작성: 2026-08-04 (환불 결함 H-1 수정과 함께)

## 지금 걸려 있는 안전판

`lib/refund-policy.ts`의 `decideRefund()` — 전 품목 가상상품 주문은 **무조건 `mode:"review"`(관리자 확인)** 로 내려간다. 즉시 자동환불(`auto`)이 나가지 않는다.

- **왜**: 가상상품의 **사용 여부를 알 수 있는 스키마가 없다.** `user_items`(`box/supabase_shop_coins_migration.sql:11-18`)는 `(user_id, item_key, quantity)`만 갖고 있어 "이미 썼는지"를 판정할 수 없다. 그대로 두면 **이미 사용한 가상상품도 무인 즉시환불**되어 상품 편취가 성립한다.
- **지금 손해 없음**: 가상상품 등록 건수 0. UX 저하 없이 미리 잠가둔 상태다.
- **누가 나중에 가상상품을 등록해도** 이 가드가 자동으로 걸려 즉시환불 사고가 나지 않는다.

## 안전판을 풀기 전(= auto 재허용 전) 반드시 끝낼 것

- [ ] **1. 사용 이력 스키마** — 가상상품 지급·사용 이력 테이블을 만들거나 `user_items`에 소비 시각(`consumed_at`)·소비 수량 컬럼 추가. 마이그레이션은 `box/`에 SQL로 작성하고 롤백 주석 동봉.
- [ ] **2. 정책 입력 전달** — `RefundOrderInput`에 사용 여부(`virtualUsed` 또는 `usedCount`)를 추가하고, `buildRefundOrderInput`(`lib/refund-executor.ts`)과 주문 상세 화면(`app/(main)/shop/orders/[id]/page.tsx`) **양쪽 모두**에서 같은 근거로 채울 것. 한쪽만 채우면 화면 안내와 서버 판정이 갈린다.
- [ ] **3. 분기 복원** — `decideRefund`의 가상상품 분기에서 **미사용이 확인된 건만** `auto`, 사용 이력이 있으면 `review` 유지.
- [ ] **4. 테스트** — `tests/refund-policy.test.mjs`에 "사용한 가상상품은 auto로 안 나간다" 케이스 추가.
- [ ] **5. 고지 일치** — 가상상품 환불 조건을 `/shop/policy`(`app/(main)/shop/policy/page.tsx`) 문구와 대조. 코드와 고지가 다르면 그 자체가 전자상거래법 위반 소지.

## 함께 확인할 것 (가상상품 특유의 함정)

- [ ] `hasPhysicalItem`/`allVirtual` 판정 근거가 주문 상세 화면에서는 **배송지 유무(`recipient_address`)를 프록시로** 쓴다(`shop/orders/[id]/page.tsx:130-132`). 실제 상품 플래그(`products.is_virtual`)를 쓰는 서버 판정과 어긋날 수 있으니, 가상+실물 혼합 주문을 허용할 거면 이 프록시부터 교체할 것.
- [ ] 기한 규칙: 가상상품은 **배송성 사유(배송지연·오배송)로 기한을 늘릴 수 없다**(H-1로 차단됨). 단 진짜 하자·품절은 법정 기한(90일)이 그대로 적용된다 — 이 구분을 바꾸려면 법률 검토 먼저.
- [ ] 환불 시 **재고 복원 대상이 아님**을 확인(`increment_product_stock` 호출이 가상상품에 무의미하게 나가는지).
