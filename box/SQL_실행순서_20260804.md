## 1단계 — cat-photos 익명 목록조회 차단 🔴 지금 실제로 새고 있음

**왜**: 익명 키만으로 유저 UUID 폴더 **80개**와 각 폴더의 파일명·업로드 시각·크기가 열거됩니다.
"누가 언제 몇 장 올렸는가"가 통째로 열린 상태입니다. (대조군 circle-photos는 0개 = 정상)

**주의**: 버킷을 private으로 바꾸지 마세요. 공개 지도의 고양이 사진이 전부 깨집니다.
여기서는 정책 기반 SELECT(=list)만 authenticated로 좁힙니다. 공개 URL 직접 접근은
버킷의 public 플래그가 담당하므로 영향받지 않습니다.

```sql
drop policy if exists "cat_photos_read_public" on storage.objects;

create policy "cat_photos_read_authenticated"
  on storage.objects for select
  to authenticated
  using (bucket_id = 'cat-photos');
```

**검증 (둘 다 필수)**
- ⓐ 브라우저 **시크릿창**에서 고양이 사진이 실린 지도/상세를 열어 **이미지가 여전히 보이는지**. 안 보이면 즉시 아래 롤백.
- ⓑ 익명 목록조회가 막혔는지 — 아래 3단계 뒤 "전체 검증" 참조.

**롤백**
```sql
drop policy if exists "cat_photos_read_authenticated" on storage.objects;
create policy "cat_photos_read_public" on storage.objects for select using (bucket_id = 'cat-photos');
```

## 전체 검증 (실행 후 한 번에)

아래를 Claude에게 그대로 요청하시면 익명 키로 프로브해 확인해 드립니다.
직접 하시려면 SQL Editor에서:

```sql
-- 2단계 반영 확인 — 컬럼이 보이면 성공
select column_name from information_schema.columns
 where table_schema='public' and table_name='orders' and column_name='user_deleted_at';

-- 3단계 반영 확인 — 테이블이 보이면 성공
select tablename from pg_tables where schemaname='public' and tablename='rally_participations';

-- 1단계 반영 확인 — cat_photos_read_authenticated 하나만 남아야 정상
select polname from pg_policy where polrelid='storage.objects'::regclass and polname like 'cat_photos%';
```
