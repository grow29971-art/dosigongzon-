## 2. 정산 카드 일일 스냅샷 (사장님 지시: 구매 즉시 아닌 하루 1회 갱신)

- 집계 로직은 `lib/fund-settlement.ts`로 추출(공개 API·크론 공유). 공개 API는 스냅샷만 읽고, 없으면 라이브 폴백.
- 카드 라벨 "실시간 공개" → **"M.D HH:mm 기준 · 매일 갱신"** (실시간 아닌데 실시간 표기는 허위표시).
- 부수효과: 구매 직후 총액 변화로 개별 주문액이 역산되던 프라이버시 구멍 차단.

- ⏳ **내일 아침 daily-dispatch가 fund-snapshot을 자동 발화하는지 cron_runs 하트비트 확인 필요.**

## 3. 관리자 후원금 관리 (/admin/fund 확장)
- **모인 금액 수동 조정**: `fund_adjustments` 장부(SQL 16) — 증액(+)/감액(−) + **사유 필수**, 삭제 시 원복. 스냅샷 직접 덮어쓰기가 아니라 건별 사유가 남는 장부 방식(투명 정산 원칙).
- **카드 반영 제어**: 상단에 공개 카드 기준 시각 표시, 라이브 값과 차이나면 주황 경고, **"카드에 지금 반영"** 버튼(`/api/admin/fund-refresh` GET=라이브/POST=스냅샷 갱신).
- **실측**: 조정 +1,234 → 스냅샷 → 공개 API 반영 → 원복까지 끝-끝 확인.
- ⚠ **사건**: 첫 "실행완료" 통보가 실제 미반영이었음(service 프로브 404) → 재실행으로 해결. **SQL 실행 통보도 반드시 프로브 실측** 원칙 재확인.
