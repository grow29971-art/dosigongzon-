# 서클 채팅 사진 비공개 전환 전략 (2026-07-26)

## 문제
회원제 서클 채팅 사진이 **공개 버킷** `cat-photos`(경로 `circle/{uid}/…`)에 저장됨.
URL만 알면 비멤버·비로그인도 열람 가능 → 멤버 전용 콘텐츠의 공개 노출.

## 새 구조 (이번 패치)
| 항목 | 값 |
|---|---|
| 버킷 | `circle-photos` (**private**) |
| 경로 규약 | `{circleId}/{senderUid}/{uuid}.webp` |
| 업로드 권한 | storage RLS — 본인 uid 폴더 + 해당 서클 owner/accepted 멤버만 |
| DB 저장값 | `circle_messages.image_url = "private:{경로}"` (URL 아님) |
| 열람 | `/api/circle/image-url`이 멤버십 검증 후 **5분 TTL signed URL** 발급 (직접 SELECT 정책 없음) |

## 기존 공개 이미지 호환성
- 기존 메시지의 `image_url`은 `https://…cat-photos/circle/…` 공개 URL 그대로 유지.
- 렌더러(`ChatImage`)가 값으로 분기: `private:` 접두 → signed URL 해석, `http…` → 기존 방식 그대로.
- 즉 **롤아웃 순서와 무관하게 기존 사진은 계속 보인다.** 코드가 먼저 배포되고 SQL이
  아직이면 "새 사진 첨부"만 명확한 에러로 실패(fail-closed), 채팅 자체는 정상.

## 롤아웃 순서 (권장)
1. `box/supabase_circle_photos_private_migration.sql` 실행 (idempotent)
2. 코드 배포
3. 채팅에서 사진 1장 첨부 → 표시 확인, 로그아웃/비멤버 계정으로 signed URL 만료(5분) 후 접근 불가 확인

## 레거시 사진 이관 (선택 — 소급 보호)
기존 공개 사진도 비공개로 옮기려면 (현재 서클 사용자가 극소수라 수동으로도 충분):
1. **복사**: Storage에서 `cat-photos/circle/{uid}/{file}` → `circle-photos/{circleId}/{uid}/{file}`
   - 주의: 기존 경로에는 circleId가 없음 → `circle_messages`에서 해당 image_url의 circle_id를 조회해 결정
2. **DB 갱신**: `update circle_messages set image_url = 'private:{새경로}' where image_url = '{옛 공개 URL}';`
3. **원본 삭제**: `cat-photos/circle/…` 객체 삭제 (public URL 무효화)
4. 소급 이관 전까지는 옛 사진의 공개 노출이 유지됨 — 민감 사진이 확인되면 해당 건만 우선 이관

이관용 SQL 헬퍼(조회 전용, 운영에서 실행해도 안전):
```sql
-- 이관 대상 목록: 공개 URL을 쓰는 서클 메시지
select id, circle_id, sender_id, image_url, created_at
from public.circle_messages
where image_url like '%/cat-photos/circle/%'
order by created_at;
```

## 리스크
- signed URL은 5분간 전달 가능(스크린샷과 동급 위험 수용). TTL 축소 가능(60초)하나 UX 저하.
- `circle_messages` 자체 RLS가 이미 멤버만 SELECT 허용이므로 `private:` 참조 문자열
  노출면도 멤버로 한정됨. 참조를 알아도 API가 멤버십을 재검증한다.
