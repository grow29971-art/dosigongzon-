## 5. Feature flag / Kill switch 설계 원칙

### 원칙
1. **기본값 off** — flag 미설정·판독 실패 시 무조건 기존 동선으로 동작 (fail-closed).
2. **단계당 flag 1개** — 여러 변경을 한 flag에 묶지 않는다. 끌 때 무엇이 꺼지는지 명확해야 한다.
3. **kill switch = 환경변수** — Vercel Dashboard에서 값 변경 + 재배포만으로 코드 revert 없이 즉시 차단 가능해야 한다.
4. **DB 스키마와 분리** — flag를 꺼도 스키마·데이터는 건드리지 않는다. 롤백 부담 최소화.
5. **flag 제거는 P8에서만** — 안정화 판정 전에는 코드에서 flag 분기를 지우지 않는다.
6. 클라이언트 노출이 필요한 flag만 `NEXT_PUBLIC_` 접두어 사용, 서버 전용 판단은 접두어 없이.
