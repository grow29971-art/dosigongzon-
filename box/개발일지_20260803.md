## 1. 라이브로 뚫려 있던 것들 — 실행·검증 완료 (제 anon 프로브로 확인)

### 🔴 공개 definer 뷰 익명 쓰기 (Critical, 라이브였음)
- `profiles_public`·`cats_public_map` 뷰가 `security_invoker=off`(소유자 권한)라 RLS 우회.
  Supabase 스키마 광역 grant로 anon/authenticated 쓰기 권한이 뷰에 자동 상속돼,
  **anon 키만으로 전 회원 프로필·전 고양이 데이터 PATCH/DELETE가 실제로 커밋됐다**(보안 패널이 침투로 확증).
- 조치: 두 뷰의 INSERT/UPDATE/DELETE 회수(`supabase_public_view_write_revoke_migration.sql`).
  실행 후 anon 재프로브 → PATCH/DELETE=401(과거 204), SELECT=200(읽기 보존). 5개 뷰 전수 감사(악용가능 0).
- 근본원인: 신규 뷰가 default privileges로 쓰기권한을 상속 → P1로 `ALTER DEFAULT PRIVILEGES` 하드닝 과제 남김.

### 🔴 profiles authenticated 교차덤프 (유일한 라이브 데이터 유출)
- base SELECT 정책이 `USING(true)`라, **로그인만 하면 전 회원의 invite_code·coins·invited_by·
  마케팅수신동의를 REST로 덤프** 가능(anon은 이미 컬럼 revoke됨, 위험 주체는 authenticated JWT).
- 조치(순서 준수): ① RPC 2종(get_inviter_code·total_user_count) ② base RLS self+admin 잠금.
  `supabase_profiles_lockdown_rpcs_migration.sql` + `supabase_profiles_authenticated_lockdown_migration.sql`.
- **검증(핵심)**: 실행 후 anon `profiles?select=id` 카운트가 **345→0행**. 0행이라는 건 잔존
  permissive 정책이 없다는 뜻 = 잠금이 실제로 걸렸고 로그인 유저도 본인 행만 보인다.
  앱 무영향 확인: profiles_public 347·total_user_count() 347 정상.

### 🟠 add_cat_card_exp 무한 EXP 파밍 (STEP 1의 진짜 구멍)
- RPC가 "최근 2분 내 내 care_log 존재?"만 보고 **그 로그가 이미 EXP에 쓰였는지는 안 봄** →
  로그 1건 만들어두고 RPC를 직접 연타하면 무한 EXP. 사진 게이트·쿨다운을 얹어도 이 RPC가 그 위를 넘어감.
- 조치: `care_logs.card_exp_awarded_at` 컬럼 + `FOR UPDATE SKIP LOCKED`로 미소비 로그 1건을
  원자 선점·소비. 로그 1건 = EXP 1회. 시그니처 불변(앱 무변경). `supabase_care_exp_consume_migration.sql`.
- 검증: anon으로 `care_logs.card_exp_awarded_at` 컬럼 존재 확인 = 마이그레이션 적용됨.
