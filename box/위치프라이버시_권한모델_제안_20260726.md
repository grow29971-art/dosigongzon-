# 고양이 좌표 정밀도 권한 모델 — 현황 조사 + 최소 개선안 (2026-07-26)

> 지시: 큰 변경 전 **제안만**. 코드 변경 없음. 데이터/UX 호환성 확인 후 별도 승인 하에 진행.

## 현재 권한 모델 (조사 결과)

좌표는 **3중 퍼징**이 겹쳐 있다:

1. **저장 시** (`lib/cats-repo.ts` `applyStorageOffset`, 주석 기준 ±444m):
   등록·수정 시 DB 저장 직전 랜덤 오프셋. 실제 급식소 좌표는 DB에도 없음.
2. **표시 시** (`getDisplayCoord` / `roamCoord`):
   - 비로그인: `fuzzCoord(…, 500)` 추가 → 저장 오프셋과 합산 **최대 ±900m**
   - 로그인: **저장 좌표 그대로**(추가 퍼징 0). 즉 로그인 = ±444m 수준 정밀도
3. **anon REST 직접 조회 차단** (`supabase_cats_anon_coord_lockdown_migration.sql`):
   STEP A(뷰 `cats_public_map`, 지터 ±약460m) 신설. STEP B(base 테이블 anon의 lat/lng 컬럼 revoke)는
   **코드 이관 배포 후 실행 게이트**로 대기 중.

### 핵심 취약점
- **일반 로그인만 하면 누구나 ±444m 좌표**를 얻는다. 가입은 이메일/소셜로 사실상 무료 →
  "검증된 돌봄 관계자"와 "방금 가입한 익명 계정"이 **동일한 정밀도**를 본다.
- 학대 표적화 리스크는 로그인 장벽 하나로만 막혀 있음(사실상 없는 장벽).
- 저장 오프셋 ±444m는 되돌릴 수 없음(원본 미저장) → 로그인 유저도 정확 위치는 못 얻지만,
  ±444m는 도시 골목 단위에선 급식소를 좁히기 충분할 수 있음.

## 최소 개선안 (3단계, 호환 우선)

### 안 1 — 표시 정밀도 등급을 "관계"로 분리 (권장, 코드만)
`getDisplayCoord(cat, viewer)`를 3등급으로:

| 뷰어 등급 | 정밀도 | 판정 기준 |
|---|---|---|
| 게스트(비로그인) | ±900m (현행) | — |
| 일반 로그인 | **±450m 추가 → 합산 ±약650m** (신규, 살짝 넓힘) | 기본값 |
| 관계자 | 현행 로그인 수준(추가 0) | 아래 "관계" 중 하나 |

**"관계자" 정의(추가 테이블 없이 기존 데이터로 판정 가능):**
- 해당 cat의 `caretaker_id` == 뷰어 (등록 당사자), 또는
- 해당 cat에 **돌봄 기록(care_logs)이 있는** 뷰어(직접 돌본 이력), 또는
- 등록자와 같은 **서클(caretaker_circles/circle_members accepted)** 소속

→ 신규 스키마 없이 조회로 판정 가능. 다만 지도 대량 마커에서 매 개체 관계 판정은 비싸므로,
  **뷰어가 관계된 cat_id 집합을 지도 로드 시 1회 조회**해 Set으로 넘기는 방식 권장.

### 안 2 — anon 잠금(STEP B) 마무리
코드가 이미 `cats_public_map` 뷰를 쓰도록 이관됐는지 확인 후 STEP B 실행.
(이건 이미 설계된 게이트 — 안 1과 독립적으로 진행 가능)

### 안 3 — "정밀 좌표 열람" 감사 로그 (선택)
관계자가 정밀 좌표로 상세를 여는 경로에 최소 카운트 이벤트(누가·언제가 아니라 **건수**만)
남겨 이상 접근 급증을 관측. `experiment_events`와 동일하게 PII 없는 집계.

## 호환성/리스크 체크 (진행 전 확인 필요)
- [ ] 로그인 유저 정밀도를 ±650m로 넓히면 **기존 UX(내가 등록한 고양이 정확 위치 확인)**가
      깨질 수 있음 → 안 1의 "관계자=본인 등록" 예외로 커버되는지 확인.
- [ ] 지도 마커 렌더 루프에 관계 Set 조회 추가 시 **성능**(현재 tier/뷰포트 필터와 상호작용).
- [ ] 저장 오프셋 ±444m는 이미 적용된 과거 데이터엔 소급 불가 — 신규 정책은 "표시" 단계만 바꿈.
- [ ] `roamCoord`(배회 애니메이션)도 같은 정밀도 소스를 쓰는지 → 표시 좌표 일원화 필요.
