## 1. 구매 적립 (등급별 차등)
- **문제**: 어제 코인·다마고치·출석 보상을 전면 제거. 남은 보상은 "돌봄 기록 → 주간 쇼핑 포인트"뿐이라 **구매 자체엔 적립이 0**. 산 사람에게 즉각 돌아오는 게 없었다.
- **결정**: 코인을 되살리지 않고 **기존 user_points 지갑 재사용**. 게임 잡동사니 없이 "산 만큼 포인트로 돌려받는" 표준 방식.
- **구현**: `lib/purchase-reward.ts` — 결제 성공 시 `payment_amount × 등급요율` 적립. 등급 = 과거 결제완료(paid_at) 주문 수. confirm·webhook(finalizePaid) 양쪽에서 지급하되 `grant_points`의 `(user, reason=purchase-reward:order.id)` 유니크로 **이중지급 차단**. 회원만(게스트 미적립).
- **요율**: 처음 2/3/5%로 잡았다가 마진 우려로 **1%(기본)/2%(단골 3회+)/3%(VIP 10회+)**로 하향. 표시 문구(상품 상세·체크아웃·성공화면)는 `points-config`의 `PURCHASE_REWARD_BASE/MAX_RATE`를 참조 → 앞으로 요율만 바꾸면 문구 자동 동기화.
- **주의**: 실제 적립은 `PAYMENT_ENABLED=true` 이후 작동. 지금은 코드·화면만 준비. 마진 얇은 상품(후원 10%+토스 3.3%+적립)은 상품 등록 시 원가 확인 필요.

## 3. 후원 지정 배분
- **문제 제기**: "수익 10%가 내 고양이가 아닌 다른 고양이들한테 가는 게 별로. 내 고양이한테 가게 할 수 없나."
- **트레이드오프 짚음**: 그 "집단 TNR 후원"이 소셜벤처·B2G 지원사업·언론의 간판 스토리라 완전 제거는 위험 → **완전 제거 대신 "내 아이에게 먼저" 방향**. 사장님 선택 = 비율 선택제.
- **안전 원칙**: 후원 **금액은 불변**(트리거·게스트RPC·confirm·웹훅 4곳 공유 계약 유지). orders에 배분 라벨(`designated_cat_id`, `donation_self_ratio` 0~100)만 추가.
- **구현**: 체크아웃에 "내 아이 : 동네" 슬라이더(기본 70:30, 등록묘 여럿이면 선택). `createOrderFromCart`가 본인 등록묘·0~100 검증 후 저장. 고양이 상세에 "○○에게 모인 돌봄 기금 N원" 카드 — 여러 구매자 지정분 합산이라 `cat_designated_fund` security definer 함수로 집계(anon grant). 자기 몫도 결국 그 아이 TNR·치료에 쓰이니 "수익 나눔" 정체성 유지, 남으면 동네로.
- **SQL 실행·프로브 검증**: `box/supabase_order_donation_designation_20260830.sql` — 컬럼 2개 select 200·`cat_designated_fund` anon 호출 0·ratio=200 insert 400(제약 작동). 전부 통과.
- **집행 UI는 오픈 후**: 실주문 쌓여야 검증 가능 → `/admin/fund`에 "고양이별 배정 → 병원 연계 집행" 버튼은 결제 오픈 후. 쇼핑오픈 체크리스트 5.5단계에 박제.
